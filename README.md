# 心の在処テスト

「自分には人の心があるのだろうか」という問いを、善悪ではなく **反応の設計** として測る
ウェブ人格診断です。全32問・約5分。ビルド不要の静的サイトで、GitHub Pages にそのまま置けます。

https://chikumatateshina.github.io/PersonalityTest/


## 特徴

- **6軸で測る** — 情動感応 / 視点推論 / 良心反応 / 関係接続 / 道具的志向 / 感情摩耗
- **結果が厳しくても、必ず対処法を併記する** — どのタイプにも「行動の目安」を4〜5項目付ける。
  相談を検討すべき合図と、日本国内の相談窓口も常に表示する。
- **設問から結果が推測されにくい** — 具体的な場面描写のみを使い、逆転項目と多軸負荷項目を混ぜ、
  出題順を毎回シャッフルする。「優しい人に見える答え」を狙いにくくしてある。
- **結果をグラフで示す** — 6軸のレーダーチャート（あなた／そのタイプの代表像の2系列）と、
  「心の可動域」を0〜100の帯の上に置くスケール。数値は軸ごとのバーと表でも読める。
- **通信しない** — 回答も結果も、端末の外に出ない。
  （結果を送信して参加者の平均を出す機能は実装済みだが、**現在は無効**にしてある。後述）
- ライト/ダーク両対応、キーボード操作（1〜5 / Backspace）、結果 URL の共有に対応。

## 結果タイプ

| タイプ | 一言 |
| --- | --- |
| 共鳴炉型 | 他人の感情が、自分の体温を決めている |
| 静かな灯型 | 大きくは揺れない。だが、消えてもいない |
| 観測塔型 | 分かる。ただし、響かない |
| 冷たい鏡型 | 読める。そして、使える |
| 凍土型 | 動かないのではなく、止めてある |
| 空洞型 | 痛みの信号が、返ってこない |
| 規範型 | 共鳴はしない。それでも、線は守る |
| 揺れ橋型 | 深く感じる。そして、それを武器にしてしまう |

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面構造（導入 / 設問 / 結果の3セクション） |
| `styles.css` | スタイル。色はライト面・ダーク面それぞれで検証済みの青のランプを使用 |
| `data.js` | 設問・重み・タイプ定義・各軸の読み取り文（**内容の編集はここだけで完結する**） |
| `app.js` | 出題進行、採点、タイプ判定、結果描画（レーダーチャートも SVG で自前描画） |
| `collect.js` | 結果の送信と参加者平均の機能一式。**既定では無効**で、何も表示せず通信もしない |
| `server/apps-script.gs` | 集計用バックエンド（Google Apps Script）。使う場合だけデプロイする |

## GitHub Pages で公開する

1. このリポジトリを GitHub に push する。
2. リポジトリの **Settings → Pages** を開く。
3. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` にして Save。
4. 数十秒後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

ビルド手順もパッケージ依存もありません。ローカルで確認する場合は
`python -m http.server` などで配信するか、`index.html` を直接ブラウザで開いてください。

## 採点の仕組み

- 各回答 `r`（1〜5）を `x = (r - 中心) / 2` に正規化し、設問ごとの重み `w` を掛けて軸ごとに合計する。
  重みは負にもなる（逆転項目）。1つの設問が複数の軸に効くこともある。
- **回答スタイルの補正**：中心は目盛りの真ん中(3)ではなく、`3 + 0.7 × (その人の平均 - 3)`。
  道具的志向と感情摩耗には逆転項目を置けていないため、素点のままだと「全部そう」と
  答えるだけで両軸が振り切れてしまう。補正後、一律回答での振れ幅は 100 → 30 に縮む。
- 軸スコア = `50 + 50 × (合計 / 重みの絶対値の合計)` を 0〜100 に丸める。
- 総合値「心の可動域」 = 感応・視点・良心・接続と道具的志向の反転を重み付けし、
  感情摩耗で増減させた値（`× (1 - 0.25 × (F - 50) / 100)`）。
  F=50 で等倍になるので、**すべて中立で答えると総合値はちょうど 50** になる。
- タイプ判定 = 8つの代表プロファイルとの重み付きユークリッド距離が最小のもの。
  2位との差が 1.5 未満なら「近接する傾向」として併記する（併記率はおよそ2割）。

### 既知の限界

- 道具的志向・感情摩耗は正方向の項目だけで構成されている。上記の補正で影響は大きく
  減るが、逆転項目を足すのが本来の解。項目を追加する場合はこの2軸から。
- 代表プロファイル同士の最短距離は 14.8（共鳴炉型 ↔ 静かな灯型）。この2つの間は
  判定が入れ替わりやすく、その場合は「近接する傾向」として両方が出る。

## グラフについて

- **レーダーチャート** — 6軸を上から時計回りに 情動感応 / 視点推論 / 良心反応 / 関係接続 /
  道具的志向▲ / 感情摩耗▲ の固定順で配置する（▲の2軸は外側ほど負荷が大きい）。
  塗り＋点が「あなた」、線のみが「判定されたタイプの代表プロファイル」で、両者の差が
  そのタイプからのずれにあたる。点にホバー／フォーカスすると両系列の値が出る。
- **心の可動域スケール** — 総合値を 0〜100 の帯（閉じている / 狭い / 標準 / 広い）の上に置く。
- 集計を有効にし、参加者が `minN` を超えている場合にかぎり、レーダーの比較対象を
  「タイプの代表像」と「参加者の平均」で切り替えられる。平均は数値表にも列として出る。
  無効のあいだ、この切り替えは表示されない。
- 依存ライブラリはなし。SVG を `app.js` で組み立てている。配色は青（あなた）と橙（代表像）で、
  ライト面・ダーク面それぞれで色覚多様性・コントラストを検証済み。

## データの送信と集計（現在は無効・将来の拡張用）

結果を送信して参加者の平均を出す機能は `collect.js` に実装済みだが、
**`COLLECT.enabled` が `false` のため停止している**。無効のあいだは、

- 同意カードも比較スイッチも **DOM に挿入されない**（`hidden` ですらなく、存在しない）
- 送信も統計取得も行わず、**通信は一切発生しない**
- 結果画面は「あなた」と「タイプの代表像」だけを描く

つまり公開ページ上では、この機能は存在しないのと同じ状態になっている。
以下は、将来ふたたび有効にするときの手順と仕様。

### 送信されるもの / されないもの

| | 内容 |
| --- | --- |
| 送る | 6軸のスコア（0〜100の整数）、心の可動域、判定されたタイプID、送信日（日付のみ） |
| 送らない | 設問ごとの回答、氏名やメールなどの個人情報、ID・Cookie などの識別子、送信時刻、User-Agent、リファラ |

- 送信は**明示的にボタンを押したときだけ**。既定では送られない。
- 送信するかどうかの選択は端末の `localStorage` に残るだけで、外には出ない。
- 平均は参加者が `minN`（既定5人）に達するまで、サーバー側が返さない。
  少人数の平均からは個人の値が逆算できてしまうため。

### 将来、集計を有効にする手順

1. Google スプレッドシートを新規作成し、**拡張機能 → Apps Script** を開く。
2. `server/apps-script.gs` の中身を貼り付けて保存する。
3. **デプロイ → 新しいデプロイ → 種類「ウェブアプリ」**。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. `collect.js` の先頭を2箇所だけ書き換える。触るのはこのファイルだけでよい。
   ```js
   const COLLECT = {
     enabled: true,                                              // false → true
     endpoint: 'https://script.google.com/macros/s/.../exec',    // 3 で発行された URL
     minN: 5
   };
   ```
5. push すると、結果画面に送信の質問が出るようになる。データは `responses` シートに1行ずつ溜まる。

`apps-script.gs` 側の `MIN_N` は `collect.js` の `minN` と揃えておくこと。
止めるときは `enabled` を `false` に戻せば、送信も表示も即座に消える。

### 公開する側の責任

集めるのは匿名の6つの数値だけだが、第三者からデータを受け取ることに変わりはない。
公開先の規約に応じて、利用目的と保存期間を書いたページを用意しておくとよい。
集計をやめるときは `collect.js` の `enabled` を `false` に戻せば、送信は即座に止まる。

## 設問や文言を変えたい場合

`data.js` だけを編集してください。設問数は自動で反映されます（`ITEMS` の長さが表示や URL 復元に使われる）。
タイプを増やす場合は `TYPES` に `target`（6軸の代表値）を含むオブジェクトを追加します。

## 注意

医学的診断ではありません。自己観察のための道具であり、結果は体調や時期によって変動します。
生活に支障が出ている場合は、テストの結果にかかわらず専門機関に相談してください。
